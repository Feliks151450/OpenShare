# OpenShare 全量 Bug 修复方案

按用户决策：deploy.sh 同步改显式开关；HTML 自定义路径渲染保持现状（document.write 不动，标记为已知接受风险）；管理端只读接口收紧权限并同步前端。

## 一、P0：部署数据丢失与覆盖上传

### 1. deploy.sh 重写同步逻辑（deploy.sh）
- 删除 mtime 自动比较覆盖（26-45 行）。
- 新增 `--sync-db-from-dev` 显式开关：**先停旧生产进程 → 用 `sqlite3 "$DEV_DB" ".backup '$PROD_DB'"` 安全导出**（自动合并 WAL，避免裸 cp）→ 再构建启动。sqlite3 不可用时回退 `cp $DEV_DB $PROD_DB $DATA_DIR/`（连同 -wal/-shm 一起拷贝且服务已停止）。
- 移动"停旧进程"到构建之前（当前在最后才停，热拷贝/热构建有竞态）。
- session secret 持久化：保存到 `$DATA_DIR/session_secret`（0600），存在则复用；生成改 `openssl rand -hex 32`，回退 `od -An -N32 -tx1 /dev/urandom | tr -d ' \n'`（修掉空 secret 回退）。
- 增加 `--foreground` 前台选项（当前 DAEMON=true 死分支）；separated 模式构建前 `rm -rf build/static`；kill 后循环等待退出 + SIGKILL 兜底。

### 2. 覆盖上传数据丢失（backend/internal/service/public_upload_service.go + repository/upload_repository.go）
- overwrite 分支：`RemoveManagedFilePermanently(destPath)`（261 行）→ 改 `MoveManagedFileToTrash(destPath)`（旧文件可恢复）。
- `UpdateExistingFileMetadata` 新增按 relativeDir 定位子目录：新增 repo 方法 `FindFolderIDBySourceSubdir(rootID, relativeDir)`，用目标子目录 folder_id（而非只查 root）匹配旧记录；匹配不到则视为新文件。
- `UpdateExistingFileByID`：更新 map 增加 `folder_id`（指向本次目标目录）；统计调整改为旧目录 `(-size,-1)` + 新目录 `(+size,+1)`；旧磁盘文件删除改 trash。
- `rollbackDirectPublishedUploads`（357 行）：错误收集继续循环（`errors.Join`），不再提前 return。
- 两个 overwrite 错误路径补 rollback 调用（当前 261/265 行失败直接 return 不回滚）。

## 三、数据一致性

### 9. 磁盘/DB 操作顺序统一改造（核心模式：磁盘操作放进 DB 事务窗口内，commit 失败做磁盘补偿）
repo 层拆出 `*Tx(tx)` 变体：`DeleteFileWithLogTx`、`DeleteFolderTreeWithLogTx`、`MoveFileToFolderTx`、`UpdateFileMetadataTx`、`UpdateFolderTreePathsTx`（原函数保留转发）。service 层编排：
- **DeleteFile**（delete.go:15-59）：`tx := repo.BeginTx` → DB 删除（未提交）→ 磁盘 trash/永久删除 → commit；磁盘失败回滚 tx；commit 失败且 trash 分支 → 文件从 trash 移回原位。
- **DeleteFolder**（79-98 行）：同型，整树 trash 移回补偿。
- **MoveFile**（move.go:87-114）：tx（folder_id + 双向统计）→ 磁盘移动 → commit；失败回滚 + 移回。物理→虚拟分支的 `RemoveManagedFilePermanently`（100 行）改 `MoveManagedFileToTrash`。
- **UpdateFile 重命名**（update.go:104-125）：tx → rename → commit；失败回滚 + rename 回旧名。
- **UpdateFolderDescription 目录改名**（folder.go:113-139）：同型。
- **ReplaceFile**（update.go:447-523）：tmp 改为同目录点前缀唯一名 `.replace-<uuid>`（rescan 忽略点文件，修复并发冲突+垃圾收编）；`io.Copy` 加 `LimitReader`（上限 = upload.max_upload_total_bytes）；替换前把旧文件复制为 `.replace-bak-<uuid>`，磁盘替换→tx 更新 size（**补 `AdjustFolderStatsTx(sizeDelta)`**，UpdateFileSize 一并改）→ commit 后删备份；DB 失败 → 备份 rename 回原位。
- **ApproveSubmission**（moderation_service.go:100-173）：repo.ApproveSubmission 拆 Tx 版本，编排进同一事务（File AfterCreate 钩子统计天然同事务）；保持"失败移回 staging"补偿。
- **RejectSubmission**（234-247 行）：顺序对调——先 DB 拒绝事务，成功后再删 staging 文件（best-effort，失败仅记日志）。

### 10. rescan 三个修复（import_rescan.go）
- service 加一把 `sync.Mutex` 串行化全部 rescan（互斥，防并发 diff 交叉污染）。
- `ApplyRescanSync` 的 DeletedFileIDs/DeletedFolderIDs 删除条件追加 `created_at <= scanStartedAt`（磁盘扫描时刻作参数传入），快照窗口内新上传不被误删。
- deletedFolderIDs 跳过条件追加"非虚拟但 SourcePath 为空的文件夹不删"（226-235 行）。

### 11. GORM OR 优先级（import_delete_repository.go:170-188）
`linkedManagedResourceScope` 改分组写法：`tx.Where(tx.Where("folder_id IN ?", folderIDs).Or("file_id IN ?", fileIDs))`（GORM 对 DB 参数加括号），确保 status 过滤作用于整个 OR 组。

### 12. 统计负数钳制（model/folder_stats.go、dashboard_stats.go）
`AdjustFolderStatsTx`/`AdjustSystemStatsTx`/`AdjustDailyStatsTx` 的 `gorm.Expr("col + ?")` 改 `gorm.Expr("MAX(0, col + ?)")`（SQLite 标量 MAX）。

### 13. SQLite 连接级 PRAGMA 失效（pkg/database/sqlite.go）
- `buildDSN` 把白名单 PRAGMA 翻译成 mattn DSN 参数（`_foreign_keys=on`、`_busy_timeout=5000`、`_journal_mode=WAL` 已有），每个新建连接自动生效；`applyPragmas` 保留兜底。
- `ConnMaxLifetime` 10 分钟 → 0（单连接长活，不再周期重建）。

### 14. 回收站位置入账（resource_management_delete.go）
DeleteFile/DeleteFolder 把 trash 返回路径写进 operation log detail（JSON 含 `trash_path` 字段），使"移到回收站"至少可人工追溯恢复。
